# 天堂私服 | 2.70C POE 詞綴 POOL 發想

## 章節用意

本篇依據 [105_2.70C對話檔世界觀語料Wiki框架](./105_2.70C對話檔世界觀語料Wiki框架.md)，整理一份可轉換為原始 POE schema 的前綴、後綴與獨特詞綴候選池。

本篇不是 JSON pool，不內嵌 JSON。目標是先建立大量命名與設計候選，後續再挑選、平衡並轉成正式 JSON。

## Schema 對應原則

每一列候選都對應原始 schema 的欄位，不新增欄位、不改變 schema 結構。

```text
id           -> 轉 JSON 時的 id 基底，可加 _t1/_t2/_t3
name         -> 詞綴名稱
group        -> 同組互斥詞綴 group
tier         -> 1/2/3，T1 最高
min_ilvl     -> 建議最低 item level
weight       -> 建議權重
stats        -> 只放一個原始 allowed_stat_key
item_kinds   -> 可出現的物品類型
```

能力設計限制：

- 不把能力改成複合能力。
- 每個詞綴候選只對應一個 `stat_key`。
- 不新增 `allowed_stat_keys` 以外的能力。
- 若未來要複合能力，應另開系統或另定特殊規則，不在本 pool 混入。

前後綴命名規則：

- 前綴：純形容詞或來源形容詞，例如「殷海薩的」「亞丁守護團的」「精靈守護的」。
- 後綴：名詞或名詞短語，不限制字數，可承載世界觀辨識度，例如「格蘭肯的淚水」「伊娃之三叉戟」。
- 獨特詞綴：用於 `specials`，保留給四龍、真冥皇、卡瑞、世界樹等高辨識來源。

建議權重：

```text
T3: 120-180
T2: 40-80
T1: 5-25
special: 3-10
```

## 轉 JSON 注意事項

- 本篇是 pool 發想，不是最終 JSON。
- 轉換時，請將每一列的 `stat_key` 轉為原始 schema 的 `stats` 物件，例如 `mr: 8-15` 轉成 `"stats": { "mr": [8, 15] }`。
- 每個候選只轉出一個 stat key，不要把同列或同主題合併成複合能力。
- 若同一 `group` 有多個 tier，轉 JSON 時通常使用同一 group，避免同組詞綴同時出現在同一裝備上。
- `specials` 建議只允許 `LEGENDARY` 或活動/首領掉落使用。
