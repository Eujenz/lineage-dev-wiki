# 天堂私服 | 2.70C 內建對話檔語料取樣與實務準則

## 前言

前面 093~103 篇章分別從 NPC 對應、文字對話檔、圖片對話檔、
`link`、`action`、傳送師、道具與圖片假動畫等角度說明對話檔。

本篇補上一個比較工程實務的角度：直接觀察 2.70C client 內建抽出的
大量 `html` 對話檔，整理出「實際被大量使用、相對可靠」的寫法。

這份取樣不是 HTML 標準文件，而是 2.70C 天堂客戶端對話框解析器的
實務經驗整理。客戶端不是瀏覽器，請優先相信內建檔案的慣例。

## 取樣範圍

本次取樣來源是一份 2.70C client 抽出的對話檔資料夾：

```text
對話檔/
```

統計結果如下：

```text
*.html 檔案數: 5388
```

主要標籤出現狀況：

```text
<body>          4856 files
<html>           282 files
<font>          4793 files
<p>             4242 files
<br>            4847 files
<a>             2426 files
<img>            967 files
<var src="#n">   340 files
<username>       394 files
<name>            54 files
```

主要屬性使用狀況：

```text
action="..."    1526 files
link="..."      1932 files
```

本次取樣中，沒有看到值得作為可靠慣例的 `input`、`table`、`button`
類表單或排版標籤。

## 最可靠的基本子集

如果是要做穩定的 2.70C 對話檔，建議先只使用以下子集：

```html
<body>
<font fg=ffffff><p align=left>標題：</p></font>
<br>
文字內容<br>
<a link="otherpage">前往靜態頁</a><br>
<a action="serverAction">送回伺服器處理</a><br>
<img src="#331" link="mainpage"></img>
</body>
```

實務準則：

- 檔名使用 `xxx-c.html`。
- 中文內容請使用 Big5 編碼。
- 多數內建檔案以 `<body>` 為主，不一定需要外層 `<html>`。
- 文字顏色使用 `<font fg=ffffff>`，不要依賴標準 HTML 的 `color`。
- 換行優先使用 `<br>`，段落可使用 `<p>`。
- 需要玩家名稱時使用 `<username>`。
- 需要 NPC 名稱或名稱欄位時可觀察 `<name>` 的既有用法。

## link 與 action 的分工

### link：純客戶端跳頁

`link` 適合用在不需要伺服器重新判斷狀態的頁面。

常見例子：

```html
<a link="tscrollp3">第2章 - 有關村莊</a><br>
<img src="#331" link="gotham"></img>
```

適合場景：

- 說明頁。
- 幫助頁。
- 書本、卷軸的靜態章節。
- 返回上一個固定頁面。

### action：送回伺服器處理

`action` 適合用在下一步必須由伺服器判斷的情境。

常見例子：

```html
<a action="deposit">存入倉庫</a><br>
<a action="retrieve">領出倉庫</a><br>
<img src="#312" action="buy"></img>
<img src="#314" action="sell"></img>
<a action="teleport silver-kent">肯特: <var src="#0"> 金幣</a><br>
```

適合場景：

- 買賣。
- 倉庫。
- 傳送。
- 製作或兌換。
- 任務或收藏狀態判定。
- 需要依照角色資料回傳不同頁面或不同數值的 UI。

## var src 的動態資料

內建對話檔中，`<var src="#n">` 是最常見的動態資料顯示方式。

範例：

```html
最近是 <font fg=ffffff><var src="#0">%</font>的程度。<br>
<a action="teleport silver-kent">肯特: <var src="#0"> 金幣</a><br>
<a action="teleport silver-woods">風木: <var src="#1"> 金幣</a><br>
```

伺服器送出的 data 陣列會依序對應：

```text
<var src="#0"> -> data[0]
<var src="#1"> -> data[1]
<var src="#2"> -> data[2]
```

如果 UI 上的文字會隨角色狀態改變，例如價格、進度、完成狀態、
收藏標記，就不要硬寫在 HTML 裡，應該用 `<var src="#n">`。

## 圖片慣例

圖片使用 client 內建的 `.img` 資源：

```html
<img src="#331" link="gotham"></img>
<img src="#312" action="buy"></img>
<img src="#314" action="sell"></img>
```

取樣中常見慣例：

- `#331` 很常用於返回或回上一頁。
- `#312` 常見於購買。
- `#314` 常見於販賣。

圖片也可以搭配 `link` 或 `action`，效果類似文字連結。

## 自訂 action 命名建議

雖然內建檔案中可以看到含空格的 action，例如：

```html
<a action="teleport silver-kent">肯特</a><br>
```

但自訂系統不一定能安全套用所有內建格式。不同私服端、不同封包處理、
不同 client patch 流程，都可能讓 action 解析變得脆弱。

自訂功能建議：

```html
<a action="collectionDetail34">查看收藏</a><br>
<a action="collectionList1">返回列表</a><br>
```

原則：

- 優先使用短而穩定的 action 名稱。
- 優先避免空格。
- 高風險流程可先避免標點符號。
- 若需要參數，可考慮 prefix + 數字後綴。
- 伺服器端再自行解析 action 字串。

## 動態整頁 HTML 的風險

`S_NPCTalkReturn` 的穩定模型是：

```text
html id + data[]
```

也就是 client 先找到固定的 `xxx-c.html`，再把伺服器傳來的 data 套進
`<var src="#n">` 或類似位置。

不建議把整頁 HTML 當成 data 塞進某個通用 wrapper，再期待 client 像
瀏覽器或樣板引擎一樣解析。部分環境會直接顯示替代符號本身，或出現
空白頁。

比較可靠的做法：

```text
icbook-c.html       固定列表模板
icdetail-c.html     固定詳細模板
icnpc-c.html        固定 NPC 互動模板
```

再由伺服器提供：

```text
data[0] = 狀態文字
data[1] = 價格
data[2] = 完成標記
```

## 收藏書類 UI 的建議寫法

收藏、圖鑑、成就書這類 UI 很適合模仿說話卷軸與傳送師：

- 首頁或章節頁：固定 `xxx-c.html`。
- 純說明頁：用 `link`。
- 需要角色狀態的頁：用 `action` 回伺服器。
- 完成/未完成標記：用 `<var src="#n">`。
- 返回固定頁：可用 `#331` 圖片搭配 `link` 或 `action`。

範例：

```html
<body>
<font fg=ffffff><p align=left>收藏圖鑑：</p></font>
<br>
<a action="collectionDetail34"><var src="#0"> 懷舊的歐西思</a><br>
<a action="collectionDetail200"><var src="#1"> 龍之谷遠征</a><br>
<br>
</body>
```

詳細頁：

```html
<body>
<font fg=ffffff><p align=left>懷舊的歐西思：</p></font>
<br>
完成狀態：<var src="#0"><br>
歐西思斗篷 <var src="#1"><br>
歐西思頭盔 <var src="#2"><br>
歐西思鏈甲 <var src="#3"><br>
<br>
<img src="#331" action="collectionList1"></img>
</body>
```

## 測試清單

新增或修改對話檔後，至少確認：

1. 檔名是否為 `xxx-c.html`。
2. 中文檔案是否為 Big5。
3. 是否已經透過 client patch 流程讓 client 真正吃到檔案。
4. `link` 是否只用在純靜態頁。
5. `action` 是否能被伺服器收到。
6. `<var src="#n">` 是否和伺服器 data 陣列順序一致。
7. 返回按鈕是否能正常回到預期頁面。
8. 不要只看 server log 成功，必須用 client 實際點擊確認。

## 結論

2.70C 對話檔的核心不是「能不能寫 HTML」，而是「client 實際支援的
小型 HTML-like 語法」。最穩的方向是：

- 固定檔案。
- 小型標籤子集。
- Big5。
- `link` 做靜態跳頁。
- `action` 做伺服器互動。
- `<var src="#n">` 做動態資料。

先把這些基本原則穩住，再考慮圖片、動畫或更複雜的 UI。
